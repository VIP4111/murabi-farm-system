# 04 — تدقيق الأمن والصلاحيات وسلامة البيانات

> فحوص دفاعية فقط. لم أنفّذ أي استغلال ضار، ولم ألمس أي نظام خارج البيئة المحلية.
> **لا توجد أي أسرار أو مفاتيح مكشوفة بالمستودع** — `.env` مُستثنى بـ`.gitignore`،
> و`.env.example` يحتوي قيماً افتراضية معلَنة (`change-this-to-a-random-secret-key`،
> `change-me-123`) لا أسراراً حقيقية. تحقّقت من كل الملفات المتتبَّعة.

## 2) التفويض

- **280 من 289 راوت** خلف `login_required`. الـ9 العامة مبرَّرة عدا ملاحظتين (`SEC-07`).
- **235 راوت** خلف `require_permission`. الفحص يتم على **الدور** لا على الاسم — قرار صحيح يجعل الأدوار بيانات.
- **الثغرة الحقيقية**: 45 راوت بـ`login_required` فقط. أغلبها يفوّض الفحص لخدمة، لكن
  مسارات المهام (`start`/`complete`/`fail`) تعتمد على `_claim_if_unassigned` الذي
  **يمنح أي مستخدم مصادَق ملكية أي مهمة غير معيَّنة** ثم يسمح بإنجازها — بلا أي فحص
  لـ`target_role` ولا لأي صلاحية.

**إثبات مُنفَّذ فعلياً** (`SEC-02`):

```
صلاحيات دور 'عاملة منزلية': []
قبل: حظيرة الحيوان = عزل | assignee = None
GET  /team/tasks/<id>          -> 403   ← الشاشة محمية بشكل صحيح
POST /team/tasks/<id>/complete -> 302   ← لكن الإجراء غير محمي
بعد: حالة المهمة = done | assignee = 1 | حظيرة الحيوان = حوامل
ACL_BYPASS
```

مستخدم بصفر صلاحيات أنجز مهمة لا يستطيع حتى **رؤيتها**، وحرّك حيواناً فعلياً من
حظيرة العزل إلى حظيرة الحوامل. الأنواع الأخطر التي يفتحها نفس المسار:
`feeding_schedule` (يخصم علفاً)، `protocol_step` (يغلق بروتوكول علاج)،
`isolation_check` (ينهي عزلاً صحياً).

## 3) تسريب البيانات عبر Service Worker — أخطر ما وجدته

`app/static/sw.js` يخزّن **كل رد GET ناجح من نفس الموقع** في كاش واحد
(`murabi-offline-v7`) مفتاحه الرابط فقط:

```js
const EXCLUDED_PATH_PREFIXES = ["/uploads/", "/login", "/logout"];   // سطر 35
function isCacheablePath(requestUrl, origin) { … return !EXCLUDED… }  // سطر 66
if (shouldCacheResponse(res)) { cache.put(req, res.clone()) }         // سطر 164
```

ثلاث حقائق مجتمعة تصنع المشكلة:

1. **Cache Storage نطاقه الأصل (origin)، لا المستخدم.** لا يدخل معرّف المستخدم بالمفتاح.
2. **لا شيء يمسح الكاش عند تسجيل الخروج.** `logout()` ينظّف الجلسة فقط؛ ولا يوجد أي
   `caches.delete` خارج مسار ترقية `CACHE_NAME` (`sw.js:151`).
3. **الكاش يُقدَّم كلما تأخّرت الشبكة أكثر من 4 ثوانٍ** (`NETWORK_TIMEOUT_MS = 4000`) —
   وهي بالضبط الحالة المتوقَّعة على «إنترنت المزرعة الضعيف» الذي وُضعت الآلية لأجله.

**النتيجة**: على جهاز مشترك (لوح/جوال المزرعة)، بعد خروج المالك ودخول عامل، أول تباطؤ
شبكة يعرض للعامل نسخاً مخزَّنة من صفحات المالك: `/finance/`، `/team/salaries`،
`/settings/audit`، تفاصيل الرؤوس والأسعار.

**التضخيم الحرج**: `/settings/backup/export-now` مسار **GET** يعيد **تفريغاً كاملاً
لقاعدة البيانات بصيغة JSON، شاملاً `users.password_hash`** — وهو مسار قابل للتخزين
بالكاش لأنه لا يطابق أي استثناء. تحقّقت من الرد فعلياً:

```
GET /settings/backup/export-now
Content-Type: application/json ; Content-Length: 157167
Cache-Control: no-cache        ← لا يمنع cache.put إطلاقاً
```

`shouldCacheResponse` يعيد `true` (الرد `ok` ولا يحتوي `/login`)، فيُكتب الملف كاملاً
في كاش المتصفح ويبقى بعد الخروج.

**درجة الثقة**: الآلية مؤكَّدة بقراءة الكود سطراً بسطر؛ العرض الفعلي على متصفح حقيقي
لم أستطع تنفيذه بهذي البيئة (لا Cache Storage API خارج المتصفح).

## 4) بقية الفحوص الدفاعية

| المحور | النتيجة |
|---|---|
| حقن SQL | ✅ **نظيف**. صفر استعلام نصي مبني من مدخلات. الاستثناء الوحيد `factory_reset_service.py:50` (`TRUNCATE`) وأسماء الجداول من `db.metadata` لا من المستخدم. |
| XSS | ✅ Jinja autoescape مفعّل، **صفر `|safe` بكل القوالب**. `Markup` مستخدَم مرة واحدة (`chat_format`) وبعد `escape()` صريح. |
| CSRF | ✅ `CSRFProtect` عام. كل نموذج POST يحمل `csrf_token` (تحقّقت آلياً من 107 قالب). الاستثناء الوحيد `/telegram/webhook` محميّ بـ`X-Telegram-Bot-Api-Secret-Token`. |
| SSRF | ✅ لا يوجد أي مسار يجلب رابطاً يحدّده المستخدم. الاتصالات الخارجية لثوابت فقط. |
| حقن أوامر | ✅ صفر `eval`/`exec`/`subprocess`/`os.system`. |
| Path traversal | ✅ `resolve_backup_path` يتحقق بـ`realpath` + `basename`؛ `/uploads/` عبر `send_from_directory` (`safe_join`). |
| رفع الملفات | 🟡 فحص الامتداد والحجم فقط — **بلا فحص نوع المحتوى الفعلي (magic bytes)**. الاسم يُستبدل بـUUID (جيد). `MAX_CONTENT_LENGTH = 10MB`. |
| الروابط الموقَّعة | 🟡 `secrets.token_urlsafe(24)` (192 بت) — قوي. لكن المقارنة `token != fs.sales_catalog_token` غير ثابتة الزمن. |
| تحديد المعدل | 🟡 موجود على 8 مسارات حسّاسة (`RateLimitHit`)، **غائب عن الدخول** وعن أغلب مسارات الكتابة. |
| رسائل الخطأ | ✅ صفحات 403/404 عربية بلا تفاصيل تقنية. لا يوجد `errorhandler(500)` ⇒ صفحة Werkzeug العامة (بلا traceback لأن `debug=False` تحت gunicorn). |
| رؤوس الأمان | ❌ **صفر**. لا `Content-Security-Policy`، لا `X-Frame-Options`، لا `X-Content-Type-Options`، لا `Referrer-Policy`، لا `Strict-Transport-Security`. تحقّقت من الرد الفعلي. |
| تسجيل بيانات حساسة | ✅ لا تسجيل لكلمات مرور أو رموز. التحذيرات تسجّل نص الاستثناء فقط. |
| أمن GitHub Actions | 🟡 الإجراءات مثبَّتة بوسم (`@v4`) لا بـSHA؛ **لا كتلة `permissions:`** ⇒ صلاحيات `GITHUB_TOKEN` الافتراضية؛ لا فحص تبعيات ولا `pip-audit` ولا CodeQL. |
| CORS | ✅ لا إعداد CORS ⇒ لا مصدر خارجي مسموح (السلوك الآمن افتراضياً). |
| المصادقة على الملفات المرفوعة | ⚠️ `/uploads/<path>` **بلا تسجيل دخول** — الحماية الوحيدة عشوائية اسم الملف. يشمل صور البلاغات، الملاحظات الصوتية، صور الوصفات الطبية، الفواتير، وصور وصولات الرواتب. |
