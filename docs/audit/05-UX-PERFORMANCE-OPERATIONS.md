# 05 — تجربة المستخدم والأداء والجاهزية التشغيلية

## أ) تجربة المستخدم

### ما هو جيد فعلاً

- **RTL واللغة العربية صحيحان بنيوياً**: `<html lang="{{ html_lang }}" dir="{{ html_dir }}">`
  محسوبان من لغة المستخدم لا من المتصفح (`app/__init__.py:inject_locale_dir`) — فنفس
  الحساب يعمل بنفس اللغة على أي جهاز. أربع لغات (ar/en/hi/am) مع اختبار اكتمال آلي.
- **واجهة مخصَّصة حسب الدور**: العامل الميداني يحصل على شاشة بخمسة أزرار كبيرة بدل
  اللوحة العامة، والقرار مبني على **الصلاحية** لا على اسم الدور (`core/routes.py:169`).
- **مستوى «بسيط جداً»** كتفضيل شخصي لكل حساب — التفاتة حقيقية لمستخدم غير تقني.
- **تأكيد العمليات الحسّاسة**: حذف بيانات المحاكاة وضبط المصنع يطلبان كتابة عبارة تأكيد.
- **فقّاعات شرح مكثّفة** (`tip()` macro) على مئات الحقول — 15 دفعة كوميت مخصَّصة لها.
- **الوضع الليلي** وتفضيل الكثافة محفوظان لكل حساب.
- **مؤشرات حالة أوف لاين صريحة**: شارة «بانتظار الرفع بجهازك» + لوحة مراجعة للمرفوضات
  مع زرّي «إعادة المحاولة» و«تجاهل نهائياً» — تصميم صحيح لمشكلة صعبة.

### عيوب تمنع إنجاز العمل (لا جمالية)

| العيب | الدليل | الأثر |
|---|---|---|
| **فقدان بيانات صامت من طابور الأوفلاين** | `DATA-01` — مُثبت بتشغيل فعلي | العامل يرى «تم الحفظ محلياً» ثم يختفي الإدخال بلا أي أثر |
| **عرض بيانات مستخدم آخر بعد تبديل الحسابات** | `SEC-01` | خرق ثقة وخصوصية، وقرارات مبنية على أرقام شخص آخر |
| **بطء يمنع الاستخدام مع نمو القطيع** | 7,833 استعلاماً على الرئيسية عند 200 رأس | راجع قسم الأداء |
| **لا مؤشر تركيز لوحة المفاتيح إطلاقاً** | `base.html:303` — `outline:none` على `input, select, textarea` **بلا أي بديل `:focus`** بالملف كله | استخدام النظام بلوحة مفاتيح فقط شبه مستحيل |
| **صفر ربط بين التسميات والحقول** | 528 وسم `<label>` · **0 استخدام لـ`for=`** · 33 حقلاً فقط له `id` · 8 حالات يلفّ فيها الوسم الحقل | قارئ الشاشة لا يعرف أي تسمية تخص أي حقل — النظام غير قابل للاستخدام بصرياً لضعيف البصر |
| **4 سمات `aria-*` فقط** بـ168 قالباً | `grep -c aria-` | — |
| **12 سمة `alt=` فقط** | `grep -rc alt=` | صور بلا بديل نصي |

### ملاحظات أخرى

- **الجوال**: `viewport` مضبوط، تخطيط مرن، أزرار كبيرة بوضع «مريح» — جيد عملياً.
- **الاتساق**: 1,394 سمة `style=` مضمَّنة داخل القوالب مقابل نظام تصميم جزئي بـ`base.html`.
  يعمل، لكن أي تغيير بصري شامل يتطلب تعديل مئات المواضع.
- **الحالات الفارغة والتحميل**: موجودة بأغلب الشاشات (لاحظتها بالزحف).
- **رسائل الخطأ**: عربية وواضحة ومترجَمة؛ صفحتا 403/404 مخصَّصتان. لا صفحة 500 مخصَّصة.
- **نسبة الربح**: `profit_percent = net_profit / total_out` — أي هامش على **التكلفة**
  لا على **الإيراد** (`finance/routes.py:43`). ليست خطأً حسابياً، لكنها تخالف المعنى
  الشائع لـ«نسبة الأرباح» وقد تُقرأ خطأً بقرار بيع.

## ب) الأداء

### قياس فعلي — بيئة القياس والبيانات

> **بيئة القياس (مثبَّتة، ولا تُعمَّم على غيرها):** Ubuntu 24.04 · Python 3.13 ·
> Flask test client داخل نفس العملية · **SQLite على ملف محلي** (لا شبكة، ولا اتصال
> خارجي) · عامل واحد، طلب واحد بلا تزامن · مستخدم بدور `owner`.
> **البيانات:** قطيع مولَّد آلياً بحالة `active` وحظائر خمس وقيدَي وزن لكل رأس؛
> صفر بلاغات، صفر مهام سابقة، صفر حركات مالية.
> **العدّاد:** مستمع `sqlalchemy.event` على `before_cursor_execute` (عدّ فعلي لكل
> استعلام يصل السائق، لا تقدير).

**عدد استعلامات SQL لكل طلب — أربع نقاط قياس فعلية:**

| حجم القطيع | `/` | `/animals` | `/alerts` |
|---:|---:|---:|---:|
| 50 رأساً | 1,983 | 1,035 | 897 |
| 100 رأس | 3,933 | 2,085 | 1,747 |
| 200 رأس | **7,833** | 4,221 | 3,447 |
| 400 رأس | **15,281** | 8,445 | 6,671 |

**زمن الاستجابة بنفس البيئة (SQLite داخل العملية):**

| حجم القطيع | `/` | `/animals` | `/alerts` |
|---:|---:|---:|---:|
| 50 | 1.15 s | 0.34 s | 0.25 s |
| 100 | 1.87 s | 0.73 s | 0.59 s |
| 200 | 3.13 s | 1.39 s | 1.14 s |
| 400 | 6.78 s | 2.62 s | 2.21 s |

**النمو خطّي — مقيس لا مُستنتَج**: الميل بين 50 و400 رأس =
`(15,281 − 1,983) ÷ (400 − 50) ≈ 38 استعلاماً لكل رأس` على `/`، والنقاط الأربع تقع
على الخط نفسه.

**السبب الجذري** (`PERF-01`): `home()` يستدعي `alerts_service.get_alerts()` **مرتين
كاملتين** بنفس الطلب — مرة داخل `_today_counts` (`core/routes.py:249`) ومرة داخل
`alert_counts_by_animal` (`alerts_service.py:1013`) — إضافة إلى `vaccination_counts()`.
وكل استدعاء يمرّ على 16 مصدر تنبيه، كلٌّ يجلب صفوفاً بـ`.all()` ثم يصل إلى علاقات
كسولة لكل رأس. أكثر الاستعلامات تكراراً على `/` عند 200 رأس: `animal_weights` ×1402،
`animals` ×1104، `vaccinations` ×805، `diseases` ×804، `vet_visits` ×800،
`matings` ×482.

> ⚠️ **لم يُقَس على PostgreSQL بهذا التدقيق** (قيد صريح: صفر اتصال بأي قاعدة خارجية).
> الأرقام أعلاه لـSQLite داخل العملية، حيث تكلفة الاستعلام الواحد ضئيلة ولا تشمل أي
> رحلة شبكة. على PostgreSQL تُضاف رحلة ذهاب وإياب لكل استعلام، فالمتوقَّع أن يكون
> الزمن **أسوأ** — لكن **بأي مقدار غير معلوم ولم أقِسه**، ولا يجوز الاستشهاد برقم
> بلا قياس. ما يبقى صحيحاً بأي محرّك هو **عدد الاستعلامات ونموّه الخطّي** — وهو مقيس.
> لإغلاق هذي الفجوة: شغّل نفس السكربت على نسخة PostgreSQL محلية بنفس أحجام القطيع
> الأربعة (راجع `08-OPEN-QUESTIONS.md`).

### مشاكل أداء أخرى

| البند | الحالة |
|---|---|
| الضغط (gzip/brotli) | ❌ **غير مفعَّل**. تحقّقت من الرد: لا `Content-Encoding` رغم إرسال `Accept-Encoding: gzip`. الصفحات 70–344 KB نصاً خاماً على «إنترنت المزرعة الضعيف» |
| Pagination | ❌ غائب عن القوائم الرئيسية. `/finance/` و`/animals` و`/health/pharmacy` تحمّل **كل** الصفوف (`.all()`) |
| Caching | ❌ لا كاش خادمي إطلاقاً (لا Redis ولا `functools.lru_cache` على استعلامات) |
| عمليات ثقيلة داخل الطلب | ⚠️ `catch_up_daily_tasks_before_request` يعمل **على كل طلب**؛ فتح `/alerts` يشغّل 8 مولّدات مهام تكتب بقاعدة البيانات |
| مكالمات HTTP خارجية داخل الطلب | ⚠️ `submit_report` يرسل تيليجرام (مهلة 5 ثوانٍ) وبريداً (10 ثوانٍ) **لكل مستلم بالتسلسل** داخل الطلب. 4 مستلمين = حتى 60 ثانية = مهلة gunicorn |
| مكالمات LLM بلا مهلة | ⚠️ `genai.Client(...).models.generate_content(...)` بلا `timeout` (`llm_bridge.py:101`) |
| الصور والملفات | ✅ تُخدَم من Cloudinary عند الإعداد؛ محلياً بلا معالجة أو تصغير |

## ج) الجاهزية التشغيلية

| المحور | الحالة | التفصيل |
|---|---|---|
| Health check | ✅ `/_healthz` يعيد `{"status":"ok"}` | لكنه **لا يفحص قاعدة البيانات** — يعيد `ok` حتى لو القاعدة ساقطة |
| Structured logging | ❌ `app.logger.warning` نصي فقط، بلا JSON ولا معرّف طلب ولا معرّف مستخدم |
| المراقبة والتنبيهات | ❌ غير موجودة (لا Sentry ولا أي تتبّع أخطاء) |
| معالج 500 | ❌ غير موجود؛ ولا `db.session.rollback()` عند الخطأ غير الملتقَط |
| المهام المجدولة | ⚠️ APScheduler **داخل عملية التطبيق**، فيعمل **مرة لكل عامل gunicorn** (عاملان ⇒ تشغيلان متزامنان). لا قفل موزَّع، والحارس `last_daily_tasks_auto_run` نمط قراءة-ثم-كتابة |
| Idempotency | ⚠️ مبنية بالمفاتيح المشتقّة (`crc32`) لكن **بلا قيد فريد بالقاعدة** يفرضها |
| Timeouts وإعادة المحاولة | 🟡 كل نداءات `requests` لها مهلة (5–15 ثانية) ✅؛ لا إعادة محاولة ولا circuit breaker؛ نداءات LLM بلا مهلة |
| إدارة أخطاء الخدمات الخارجية | ✅ ممتازة كفلسفة — كل تكامل يتجاهل نفسه بصمت بلا مفتاح، ولا يُسقط العملية الأساسية |
| خطة rollback | ❌ غير موجودة. `Procfile` يشغّل `flask db upgrade` بمرحلة release، و**لا يوجد أي `downgrade` مختبَر** ولا نسخة قبل الترقية |
| النسخ الاحتياطي | ❌ تصدير JSON يدوي فقط، **بلا استعادة**، بلا جدولة، وبلا اختبار. حادثة فعلية موثَّقة بالكود: انتهاء صلاحية قاعدة Postgres المجانية وضياع الوصول للبيانات |
| اتساق البيئات | ⚠️ صنف `Config` واحد لكل البيئات. `SESSION_COOKIE_SECURE` يعتمد على وجود `RENDER=true` — فالنشر على Railway (موصوف بـ`DEPLOY.md`) أو Docker/VPS يعمل بكوكي **غير آمنة** افتراضياً |
| السرّية بالإنتاج | ✅ كل شيء من متغيرات البيئة؛ لا أسرار بالمستودع |
| `flask seed` بمرحلة release | ⚠️ صار يحذف صفوف `Task` ويوقف قوالب مهام **بكل نشر** — عملية تدميرية تلقائية بمسار النشر |
| Python المطلوب | ⚠️ ≥ 3.12 فعلياً (`numpy==2.5.1`) وغير موثَّق؛ CI على 3.13 وDocker على 3.12 — لا `runtime.txt` ولا `.python-version` |
